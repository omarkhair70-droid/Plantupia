# World 03 — Living Object

Status: EXPLORATION / NOT A PRODUCT DECISION  
Date: 2026-10-07

## Provisional thesis

A smart plant product does not have to be a sensor attached to a pot.

It can be a designed object in which:

plant × furniture × spatial function × care × technology

are one composition.

The interface may live in the object itself.

## Relationship this world changes

Typical smart-home logic adds screens, apps and devices around ordinary objects.

This world asks:

> What if the technology became quieter as the object became more alive?

Possible forms include:

- planter
- divider
- desk / table element
- hospitality object
- wall / modular structure
- seating + planting composition

No form is selected yet.

## Primary experience

Most of the time the object is simply present in the space.

Technology disappears.

When a meaningful living-state change occurs, the object may communicate subtly through:

- light
- material response
- movement
- sound
- one small physical cue

The signal should invite observation of the plant, not replace it.

## Product behavior

- calm by default
- no screen required
- automate burdensome infrastructure where appropriate
- keep physical care accessible
- living state changes behavior only when meaningful
- uncertainty must not become theatrical emotion
- object ages / grows with the living system rather than pretending to stay visually frozen

## Physical / digital relationship

Physical-first.

Digital software may exist for:

- setup
- maintenance
- deeper history
- professional configuration
- service / remote monitoring

But the main daily relationship should not require staring at an app.

## Possible business

Several models remain open:

- premium object sale
- object + recurring care
- Nature-as-a-Service contract
- commercial installation
- licensing / manufacturing partnership
- later consumer version

## Why Plantupia may have a right to build it

This world becomes credible only if Plantupia can combine:

- spatial design
- living-material knowledge
- real maintenance
- industrial / furniture design
- sensing / software
- a service model that keeps the object alive

This is much harder for a pure app company.

## What this world must not become

- LED pot
- "smart planter" commodity clone
- app-controlled gimmick furniture
- pseudo-scientific plant emotion display
- hardware for hardware's sake
- object that is beautiful on launch day but impossible to maintain

## Smallest useful experiment

Do not build custom hardware first.

Build one crude but art-directed object using:

- real plant
- off-the-shelf moisture / light / environment sensing
- one subtle ambient output
- easy care access
- a visible growth / maintenance timeline

Test:

1. Can a person understand that something deserves attention without a dashboard?
2. Does the cue send them toward the plant?
3. Does the object preserve touch / inspection / care?
4. Does it still make sense after the novelty disappears?

## Kill conditions

Kill or demote this world if:

- ambient signals are less clear than simple notifications
- hardware / maintenance economics overwhelm the experience value
- the object cannot survive real commercial operations
- technology becomes the visual protagonist instead of the living system
