# World 04 — Living Materials / Specifier Infrastructure

Status: EXPLORATION / NOT A PRODUCT DECISION  
Date: 2026-10-07

## Provisional thesis

Greenery can be treated as a specification-ready living architectural material rather than decoration added near project completion.

This world begins upstream with architects and interior designers.

## Relationship this world changes

Typical project flow can make greenery a late-stage layer:

architecture → interiors → procurement → "add plants."

This world asks:

> What if living systems enter the drawing when material, furniture and spatial decisions are still being made?

The key is not a plant catalog.

It is continuity from:

design intent → viable specification → proposal → installation → as-built living record → future care.

## Primary experience

A designer works with a space or floor plan and thinks in spatial roles:

- soften a boundary
- create partial refuge
- anchor an arrival
- divide without blocking light
- create human scale
- add a living focal point

The system helps translate that intent into viable living systems under real constraints.

Potential output:

- appropriate planting system
- environmental requirements
- space / access requirements
- planter / module dimensions
- maintenance assumptions
- 3D / BIM object
- preliminary specification
- RFQ / design-support handoff

After installation, the specified object does not disappear.

It can become the starting identity of the as-built living record.

## Product behavior

- design intent before catalog browsing
- biological viability before aesthetic confirmation
- clear difference between design assumption and measured site reality
- specification data stays connected after procurement
- maintenance access is part of design
- growth / future form is acknowledged
- real product files fit existing design tools instead of forcing a closed universe

## Physical / digital relationship

Digital-first during design.

Physical consequences are direct because outputs enter actual built projects.

Possible integrations:

- Revit
- Archicad
- SketchUp
- Rhino
- IFC
- CAD
- downloadable specifications
- visualizations
- RFQ

No integration is committed yet.

## Possible business

1. Free design / specification layer that drives Plantupia project demand.
2. Professional subscription for advanced specification / portfolio tools.
3. Paid design support / consulting.
4. Manufacturer / partner marketplace later.
5. Global digital layer even when Plantupia does not perform local installation.

## Why Plantupia may have a right to build it

Plantupia would need to connect design knowledge to actual installation and maintenance outcomes.

That feedback loop can improve future specifications:

what looked good  
→ what was installed  
→ what survived  
→ what failed  
→ why  
→ what should be specified differently next time.

Without this loop, it becomes another BIM library.

## Lateral hypothesis

What if Plantupia's "material library" is not organized primarily by species?

It could be organized by spatial / living behavior:

- soft boundary
- privacy layer
- focal vertical form
- low-maintenance shaded zone
- high-touch hospitality composition
- modular living divider

This is intentionally speculative.

## What this world must not become

- pretty plant catalog
- generic 3D asset library
- Pinterest board with RFQ button
- fake automated "AI office designer"
- specification system that ignores maintenance
- proprietary workflow that architects hate using

## Smallest useful experiment

Take one real or representative office plan with three spatial problems.

Ask one designer to solve them using a prototype that provides:

- spatial intent
- environmental constraints
- 2–3 viable system directions
- technical / maintenance implications
- one exportable spec / object
- RFQ handoff

Then carry one selected concept forward into a mock as-built record.

Success question:

> Does this make greenery a design decision earlier, with less information loss later?

## Kill conditions

Kill or demote this world if:

- architects do not influence purchase early enough
- the workflow adds effort instead of removing it
- specification data cannot be made reliable
- Plantupia lacks repeatable systems / products that can be specified
- designers prefer direct consultation over self-service tooling
